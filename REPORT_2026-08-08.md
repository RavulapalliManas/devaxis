## 1. What was asked, and what exists now

The task was to execute a 52-section developmental-pretraining research plan on free Trainium
capacity, in a clean repository, optimised for the hardware.

What exists now:

- a new repository with 26 passing tests, containing generators, a training engine with three
  accelerator backends, an exact-branch engine, health gates, a metric-mutation audit, and the
  operational stack for the Trainium box;
- a certified platform: the box reproduces CPU numerics within tolerance, and a forked
  checkpoint replays its parent bitwise;
- **127 completed training runs** across five experiments (49 factorial including its canary,
  21 branch, 24 dose-response, 22 window, 11 DD10), with 28 more in flight;
- two results (one positive, one null), one refuted framing, and one live challenge to the
  positive result;
- an unattended runner that keeps executing queued experiments without a laptop attached.

## 2. What was built

### 2.1 Scientific core

| Component | Purpose |
|---|---|
| `generators/keys.py` | Every batch is a pure function of `(stream_id, "train", step)` via SHA-256 → numpy Philox. There is no loader state; the cursor **is** the step. This is what makes a branch replay its parent exactly. |
| `generators/binding.py` | The K-binding task, vectorised from flagship-04's `lag_law.py`. A latent/surface split gives exact-duplicate, paraphrase, and structural recurrence for free. |
| `training/model.py` | The 4,920,832-parameter GPT (6 layers, d=256, 8 heads, closed vocabulary of 392, context 54). |
| `training/engine.py` | One loop, backends `cpu` / `cuda` / `neuron`, two compiled graphs on Neuron, health gates, mutation hooks. |
| `training/branch.py` | Fork a checkpoint, apply an intervention as a manifest diff, and certify the result against tolerance tiers. |
| `analysis/` | Three scripts: `aggregate` builds tables, `analyse` does censoring-aware survival statistics, `verify` recomputes invariants and audits S3. |
| `audit/mutations.py` | Four sabotage injections that must each trip a named detector. |

### 2.2 Operations

Everything runs on the box under systemd, so no laptop, terminal, or SSH session is required:
`devaxis-program` (experiment runner), `devaxis-guard` (deadline), `devaxis-sync.timer`
(S3 every 10 minutes). Access is by SSM, so no SSH key is needed.

`tools/program.py` reads its phase list from `PROGRAM.json` on every iteration, so new
experiments can be appended while it runs. It judges completion by diffing the queue against
the results, resumes from saved state, revives a dead dispatcher, and abandons a stalled phase
rather than blocking.

## 3. Platform certification (all measured)

| Gate | Result |
|---|---|
| **Q0 preflight** | 16 devices / 32 NeuronCores; bf16 matmul value-correct; 32-rank all-reduce sums to exactly 496.0; S3 write-then-read-back. PASS |
| **Q2 exact-branch replay** | Fork `q4_s5` at step 4000, replay to 8000: **0.0 metric drift, 0.0 relative parameter divergence across 17 eval points. Tier T0, bitwise.** |
| **Q3 numerical equivalence** | Neuron fp32 versus a CPU fp64 oracle on the same keyed stream: max relative loss difference **2.08e-06**, against a pre-declared bar of 1.80e-05. The CPU's own fp32 error is 1.798e-06, so Neuron sits at 2.8× the platform's irreducible error. **PASS.** bf16 measures 2.39e-02, consistent with an 8-bit mantissa; it is a separate numerical condition, not certified, and not used. |

Q2 matters more than it looks. Because a no-op fork reproduces its parent exactly, any
difference between a parent and an intervened child is caused by the intervention rather than
the hardware. Every branch experiment below rests on it.

**Throughput:** 8.4 steps/s per NeuronCore for this model at batch 128, about 400 steps/s
across 32 cores.

## 4. Experiments completed

127 runs terminal, zero unexplained failures. Counts are from the run files on the box, not
from queue lengths.

### 4.1 Data-distribution factorial — 49 runs — NULL

Recurrence type (exact / paraphrase) × spacing (interval 50 / 500) × order (fixed / scrambled),
at 25% recurrence rate over a 64-program pool, 5 seeds per cell plus 8 baselines.

Primary endpoint declared before any run started: emergence step of `query_ctx ≥ 0.625`,
right-censored at the 120,000-step budget.

| Cell | n | events | censored | KM median |
|---|---|---|---|---|
| baseline | 8 | 7 | 1 | 9,750 |
| exact / short / fixed | 5 | 5 | 0 | 10,000 |
| exact / short / scrambled | 5 | 5 | 0 | 9,000 |
| exact / long / fixed | 5 | 3 | 2 | 16,750 |
| exact / long / scrambled | 5 | 3 | 2 | 12,000 |
| paraphrase / short / fixed | 5 | 4 | 1 | 17,500 |
| paraphrase / short / scrambled | 5 | 5 | 0 | 8,500 |
| paraphrase / long / fixed | 5 | 4 | 1 | 9,250 |
| paraphrase / long / scrambled | 5 | 4 | 1 | 9,500 |

Log-rank against baseline, Holm-corrected: **every cell p = 1.0**, smallest raw p = 0.197.
With 5 seeds per cell this reads as "no large effect", not "no effect".

### 4.2 Deprivation branch matrix — 21 runs — POSITIVE

Every baseline forked at step 4000, a state that is pre-emergence for all parents and
post-read for all of them. Three arms differ only in the use-supply schedule.

| Arm | n | emerged | use-supplied steps |
|---|---|---|---|
| noop (p = 1) | 7 | **7/7** | delays 3,000 / 4,500 / 4,750 / 5,750 / 6,500 / 11,500 / 27,750; median 5,750 |
| deprive (p = 0 permanently) | 7 | **0/7** | to 46,000 |
| rescue10k (p = 0 at 4k, p = 1 at 14k) | 7 | **0/7** | to 46,000 |

**Paired sign test over all 7 parents: 7/7 reversals, one-tailed p = 0.0078.** Each rescued run
had already exceeded its own control's emergence delay without emerging, so no pair can flip
and the p-value is final.

### 4.3 Dose-response — 38 runs — MONOTONE

Deprivation length τ varied at the same fork state, everything else matched.

| τ | emerged | n | rate | use-supplied steps available |
|---|---|---|---|---|
| 0 | 7 | 7 | **1.00** | 52,000 |
| 2,000 | 4 | 8 | **0.50** | 64,000 |
| 5,000 | 2 | 8 | **0.25** | 61,000 |
| 10,000 | 0 | 7 | **0.00** | 46,000 |
| 20,000 | 0 | 8 | **0.00** | 46,000 |

**Cochran-Armitage trend test: z = −3.783, one-tailed p = 7.8e-05, n = 38.**

Opportunity confound excluded: the slowest control ever needed 27,750 use-supplied steps, and
every arm received at least 1.7× that. Short τ degrades gracefully, with several runs parking
on the ~0.5 half-solved plateau; at τ ≥ 10,000 nothing leaves chance.

### 4.4 Window sweep — 22 runs — REFUTED MY FRAMING

Fixed insult (τ = 10,000) applied at five developmental ages.

| Fork age | n | emerged | final query_ctx (chance 0.25) |
|---|---|---|---|
| 1,000 | 5 | 1/5 | 0.211, 0.236, 0.250, 0.254, **0.916** |
| 2,000 | 5 | 0/5 | 0.240–0.275 |
| 4,000 | 5 | 0/5 | 0.227–0.262 |
| 8,000 | 5 | 0/5 | 0.221–0.262 |
| 12,000 | 2 | 0/2 | 0.242, 0.252 |

1 of 22 emerged, uniformly across ages. The declared predictions were "age-dependent = critical
period" and "uniform = damage, not a period". The data are uniform, so **the narrow
critical-period framing is not supported.** Dose matters; timing within the pre-emergence phase
does not.

This sweep also has a design flaw I introduced. The cell that would decide the developmental
question, depriving a model that already has the circuit, was never populated: the parents
present at ages 8,000 and 12,000 had not emerged at those steps. Ages were chosen on a fixed
grid instead of relative to each parent's own emergence step. The corrected experiment is
queued (§7).

### 4.5 Artifact audit of the positive result

Five mechanical explanations were tested and ruled out.

| Check | Result |
|---|---|
| Did the rescue happen? | 182–185 evals per run with the supply parameter at exactly 1.0 after the rescue step, 40 at exactly 0.0 during the window, zero violations in 5/5 runs |
| Did the gradient change? | Training loss jumps 0.0001 → 0.19 at the rescue step in every run |
| Is the model broken? | **recap = 1.000** (min, median, max) in both failing arms |
| Is the readout alive? | query_ctx oscillates 0.20–0.30 in failing arms; controls on the same code reach 0.91–0.95 |
| Is it learning slowly? | Over 42,000 use-supplied steps: loss 0.1863 → 0.1786, query_ctx 0.252, 0.257, 0.261, 0.252, 0.247, 0.249. Flat in all 5 runs |

## 5. What the results say

Two circuits in this task have opposite developmental character.

The **read circuit**, which maintains four bindings across a distractor gap, forms within about
500 steps and survives everything tested: recap stays at 1.000 in models deprived for 20,000
steps and trained 46,000 more.

The **use circuit**, which selects the queried binding, forms late (7,000 to 31,750 steps),
stochastically, and only when its supervision is present during the pre-emergence phase.
Withhold that supervision past a dose threshold and it does not form, even though the model
demonstrably holds the information and demonstrably receives the gradient asking it to use it.

Read against the factorial null, the pair is sharper than either alone. Changing how the data
repeats moved nothing measurable. Changing when the supervision arrives decided whether the
capability existed.

## 6. The alternative explanation now being tested

AdamW applies decoupled weight decay: every parameter is multiplied by (1 − lr·wd) on every
step, whether or not it received a gradient. Here lr·wd = 3e-3 × 0.1 = 3e-4. During deprivation
the recap tokens stay supervised, so read-circuit parameters keep receiving gradient and are
held up, which is exactly why recap stays at 1.000. Parameters serving only the answer site
receive nothing and decay geometrically.

| τ | surviving multiplier (1 − 3e-4)^τ | observed emergence rate |
|---|---|---|
| 0 | 1.000 | 1.00 |
| 2,000 | 0.549 | 0.50 |
| 5,000 | 0.223 | 0.25 |
| 10,000 | 0.050 | 0.00 |
| 20,000 | 0.002 | 0.00 |

The dose-response tracks the decay curve closely. If this is the mechanism, the result is not
developmental foreclosure; it is weight decay erasing a sub-circuit that has no gradient to
defend it.

**Status: UNTESTED. The experiment is queued ahead of all other work** (`tools/make_wd0.py`):
repeat the deprivation with weight decay set to zero from the fork onward, with a wd = 0
control and τ ∈ {10,000, 20,000} across 8 parents. Declared in advance:

- foreclosure disappears at wd = 0 → the mechanism is weight decay, the developmental framing
  is retired, and the useful claim becomes that an unsupervised sub-circuit is erased at a rate
  set by lr·wd (which predicts scaling in lr·wd·τ rather than in developmental state);
- foreclosure persists → the most plausible mundane explanation is dead;
- partial → decompose.

Nothing further should be built on the developmental reading until this reports.

## 8. Errors made, and how each was caught

Recorded because the corrections are more useful than the successes.

1. **An entire wave trained nothing for hours.** A `-inf` causal attention mask produces NaN on
   Neuron once the sequence is long enough that a softmax tile lies entirely above the diagonal,
   since −inf − (−inf) is NaN. I reported throughput without reading a loss value. A nine-arm
   bisect isolated it; `finfo.min` fixes it and is bitwise-identical in the forward pass.
   Corollary: a short-sequence smoke test cannot certify a long-sequence configuration.
2. **A speedup claim was wrong.** I attributed a 17× throughput gain to a dispatch-windowing
   change. An A/A test measured the speedup at 0.99. The gain was the compile cache warming.
   Retracted.
3. **A p-value was overstated.** I reported Fisher p = 0.0079 on unpaired arms with unequal
   parent sets, when parents differ fourfold in intrinsic emergence time. The correct paired
   test gave p = 0.125 at the time. Retracted and replaced; the design was then completed, and
   the paired test now reads p = 0.0078 legitimately.
4. **Six runs vanished silently.** Jobs launched onto NeuronCores still held by another wave
   died at runtime init and left no run record, so they were invisible to result-file counts.
   Three of them were controls. General lesson: a job that never starts is absent, not failed;
   diff the queue against the results.
5. **A self-healing routine would have corrupted data.** The live-process counter used an
   invalid `pgrep` flag and always returned zero, and the dispatcher-revival rule keyed on it.
   It would have put two dispatchers on one queue. Caught before any revival fired.
6. **A systemd trap.** A child spawned from a `Type=oneshot` unit is killed when that unit
   finishes; `start_new_session` does not save it.
7. **A design flaw in the window sweep** (§4.4): fixed ages instead of ages relative to each
   parent's emergence, so the decisive cell was never populated.

## 9. Scope

These results hold for one task family, one model size (4.9M parameters), one architecture, one
optimiser configuration, 7–8 seeds per arm, and one fork state for the dose-response. The
factorial null is powered for large effects only. The dose-response has a live alternative
explanation (§6). No claim here extends to language models at scale.

A separate session reports the same dose-response shape on different hardware (τ = 2,000 giving
7/10 and τ = 6,000 giving 0/10). That is consistent, and it is their measurement, not ours.
